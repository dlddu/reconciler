# 템플릿: E2E 모킹 최소화 (e2e-mock-policy)

한 레포에서 **E2E가 실환경을 그대로 구동하는 것**을 기본으로 두고, 결정적 치환
(네트워크 인터셉트·응답 모킹·테스트 전용 fixture seam·외부 서비스 mock 서버)은
**실환경으로 재현이 불가능한 경우에 한해, 문서에 등재된 지점만** 허용하는 모델.
정합 상태 = **불변식 1 ∧ 불변식 2**. 불변식 1은 **허용목록에 등재된 모킹 지점의
집합 == 코드에 실재하는 모킹 지점의 집합**(양방향 1:1)이고, 미등재 모킹도 고아 등재도
모두 drift다. 불변식 2는 **차단 요인**(치환이 없거나 모자라서 E2E가 그 경로를 아예
밟지 못하는 원인)이 **해소 계획을 갖는가**를 잰다 — 코드에 토큰을 남기지 않아 불변식
1이 구조적으로 볼 수 없는 부채다.

"실환경 우선"이 스펙(SSOT)이고, 예외는 **늘지 않는 방향으로만** 관리한다.

## 슬롯 표

대상 레포를 탐색해 확정한다. 확정 안 되는 값은 추측하지 말고 사용자에게 묻는다.

|---|---|---|---|
| `{{REPO}}` | owner/repo | `dlddu/kubernetes-dashboard` | `dlddu/dear-baby` |
| `{{SLUG}}` | id·이름용 소문자 레포명 | `kubernetes-dashboard` | `dear-baby` |

| `{{BLOCKER_LEDGER}}` | 차단 요인 원장의 위치(정책 문서 내 표·마커). **없으면 「아직 없음 — 첫 원인이 생기는 시점에 만든다」** | 아직 없음 | 아직 없음 |
| `{{INITIAL_STATE}}` | 등록 시점 현황(등재 수 vs 실측 지점 수, 미등재·고아 예시) | 정책 문서 부재, 인터셉트 83줄 | 경계 6건 등재, seam 32건 실측 |
| `{{NOW_ISO}}` | 등록 시각 (UTC ISO 8601) | `date -u +%Y-%m-%dT%H:%M:%SZ` | 〃 |

  "asIs": {

  스크립트가 경로 목록을 직접 다룬다(스크립트가 진실).

## versionScript

**to-be** — 정책·허용목록의 지문. 정책이 바뀔 때만 값이 변해야 한다.
문서가 **없는 상태도 유효한 관측**이므로 `absent`로 표현한다(빈 해시로 뭉개지 않는다).

*A. 전용 문서형* — 정책이 파일 하나를 통째로 차지할 때:

```bash
#!/usr/bin/env bash
# to-be = 모킹 정책·허용목록 문서의 blob hash. 아직 없으면 'absent'.
# 런타임이 dataSource.repository({{REPO}})@ref(main)를 체크아웃한 상태를 가정한다.
set -euo pipefail
git rev-parse --verify --quiet "HEAD:{{POLICY_SSOT}}" || echo "absent"
```

*B. 섹션 추출형* — 정책이 더 큰 문서 안의 한 섹션일 때(그 문서의 다른 섹션 변경에
반응하지 않도록 섹션만 잘라 해시한다). 섹션이 사라지거나 제목이 바뀌면 추출이 비어
`absent`가 되고, 이는 "정책이 사라졌다"는 올바른 drift 신호다:

```bash
#!/usr/bin/env bash
# to-be = <문서>의 "<섹션 제목>" 섹션만 추출한 sha256. 같은 문서의 다른 섹션 변경은 무시된다.
# 런타임이 dataSource.repository({{REPO}})@ref(main)를 체크아웃한 상태를 가정한다.
set -euo pipefail
export LC_ALL=C
SEC=$(git show "HEAD:{{POLICY_SSOT의 파일}}" 2>/dev/null \
  | awk '/^### <섹션 제목>/{f=1; print; next} f && /^##/{exit} f{print}')
if [ -z "$SEC" ]; then echo "absent"; exit 0; fi
# ↑ 정책이 doc-tracker의 등재 섹션이면 awk 대신 README 「doc-tracker 경로 해석」 조각을 붙이고
#   M_FILE="$(tracker_month '{{TRACKER_DIR}}')"; SEC=""; [ -n "$M_FILE" ] && SEC="$(tracker_section "$M_FILE" '### <섹션 제목>')"
#   로 구한다(월 파일 경로는 달마다 바뀌므로 파일을 직접 지정하지 않는다). dataSource.subPath는 tracker 폴더로 둔다.
echo "entries=$(printf '%s\n' "$SEC" | grep -cE '<등재 행 패턴>' || true)"   # 진단용
printf '%s' "$SEC" | sha256sum | cut -d' ' -f1
```

**as-is** — 코드에 실재하는 모킹 지점의 지문. **트리 해시를 쓰지 않는다**: 어서션·
셀렉터 등 모킹과 무관한 변경에 반응하면 자매 모델(`{{SIBLING_MODEL}}`)과 중복
트리거되고 노이즈가 커진다. 대신 `{{MOCK_PATTERN}}`에 걸리는 부분만 뽑아 정규화·
정렬·해시한다.

*라인형* — 매칭된 **줄 전체**를 지문에 넣는다. 대상 URL 패턴처럼 줄 안의 인자가
정책적으로 중요할 때(예: Playwright 인터셉트):

```bash
#!/usr/bin/env bash
# as-is = E2E의 "모킹 지점 지문". 인터셉트 호출 라인만 뽑아 정규화·정렬 후 해시한다.
# 런타임이 dataSource.repository({{REPO}})@ref(main)를 체크아웃한 상태를 가정한다.
set -euo pipefail
export LC_ALL=C
PATTERN='{{MOCK_PATTERN}}'
HITS=$({ git ls-files -- {{MOCK_SCOPE}} | grep -vE '{{SCOPE_EXCLUDE}}' | sort \
        | xargs -r grep -EH "$PATTERN" || true; } \
  | sed 's/[[:space:]]\+/ /g' | sed 's/^ //; s/ $//' | sort)
echo "sites=$(printf '%s' "$HITS" | grep -c . || true) files=$(printf '%s' "$HITS" | cut -d: -f1 | sort -u | grep -c . || true)"
printf '%s' "$HITS" | sha256sum | cut -d' ' -f1
```

*토큰형* — 매칭된 **토큰과 파일의 쌍**만 지문에 넣는다(`grep -Eo` + `sort -u`).
모킹 지점이 이름 붙은 플래그·심볼이고 주변 배선(로그 덤프·롤아웃 대기 등)이 잦게
바뀌는 레포에서 쓴다. 같은 파일 안에서 같은 토큰이 몇 번 나오는지는 지문에
반영되지 않는다 — 그 대가로 문구 수정에 흔들리지 않는다.

```bash
HITS=$({ git ls-files -- {{MOCK_SCOPE}} | grep -vE '{{SCOPE_EXCLUDE}}' | sort \
        | xargs -r grep -EHo "$PATTERN" || true; } | sort -u)
```

두 형태 모두:
- 모킹 지점이 **하나도 없는** 목표 상태의 지문은 빈 입력 sha256
  `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`로 안정적으로 고정된다.
- 마지막 줄만 버전이므로 `sites=…` 진단 줄은 값에 영향을 주지 않는다.
- 단위 테스트는 반드시 `{{SCOPE_EXCLUDE}}`로 제외한다(그 층위의 모킹은 정상이다).

## 무엇이 "맞는 상태"인가 (SSOT)
- **정책·허용목록의 SSOT**는 {{POLICY_SSOT}}다. 허용 카테고리와 승인된 모킹 지점 목록(위치 · 대상 · 카테고리 · 실환경 불가 사유)을 담는다.
- **실제 사용의 SSOT**는 코드의 모킹 지점이다: {{MOCK_SCOPE}} 범위에서 {{MOCK_KINDS}}에 해당하는 지점.
- 정합 상태 = **불변식 1 ∧ 불변식 2**. 어느 하나만 참인 것은 정합이 아니다.
  - **불변식 1 (지점 1:1)** — **허용목록에 등재된 지점의 집합 == 코드에 실재하는 지점의 집합**(양방향 1:1). 미등재 모킹도, 코드에 없는 고아 등재도 모두 drift.
  - **불변식 2 (차단 요인 = 부채)** — 아래 「불변식 2」 절.

## 허용 예외 카테고리 (이 밖은 불허)
{{CATEGORIES}} <!-- 지침: 코드/ID와 의미를 표나 목록으로. 각 항목은 "실환경으로 왜 불가능한가"를 담는다 -->

**실환경으로 준비 가능하면 어떤 카테고리도 쓸 수 없다.** 대체 수단이 아직 없다는 것은 불가능의 근거가
아니다 — 만들 수 있으면 만드는 것이 작업이다(「충돌 시 기본 방향」).

명시적 불허: {{FORBIDDEN}}.

## 표기 규약
허용된 모킹 지점은 그 지점 직전 줄에 사유 주석을 단다.

`{{ANNOTATION}}`

같은 항목이 {{POLICY_SSOT}} 허용목록에도 있어야 한다. 주석만 있고 미등재이거나, 등재만 있고 코드에 없으면 drift다.

## 불변식 2 — 「차단 요인」은 적어 두는 칸이 아니라 닫아야 하는 부채다

**차단 요인** = 치환이 아예 없거나, 있어도 표현력이 모자라서 E2E가 그 경로를 **아예 밟지 못하는**
원인. 모킹 지점이 아니므로 코드에 토큰을 남기지 않고, 따라서 **불변식 1은 이것에 대해 영원히
침묵한다** — 등재↔코드가 1:1이면 차단 요인이 몇 건이든 불변식 1의 gap은 0이다. 게이트가 개수를
찍더라도 정의가 그것을 판정 입력으로 쓰지 않으면 「기록은 되는데 부채로 추적되지는 않는」 상태가
되고, 다른 모델이 넘긴 인계가 소리 없이 유실된다.

**원장**: {{BLOCKER_LEDGER}}. 원장이 아직 없으면 **첫 원인이 생기는 시점에 만드는 것이 작업**이지,
원인을 기록하지 않을 근거가 아니다.

**개수 자체는 gap이 아니다.** 차단 요인은 즉시 해소가 불가능한 것이 대부분이라 개수를 그대로 gap으로
재면 영구 red가 되어 신호가 죽는다. 재는 것은 **해소 계획의 존재**다.

- **B1 인계 수신** — 이 모델에 해소를 넘긴 문장(출처는 {{POLICY_SSOT}}의 다른 절과 reconciler 레포
  **다른 모델**의 task 레코드 둘뿐)마다 원장에 행이 실재해야 한다. 지목됐는데 행이 없으면 gap이다.
  넘긴 쪽은 넘겼으니 처리됐다고 보고, 받는 쪽은 세지 않아 인계가 유실되는 자리가 여기다.
- **B2 계획 완비** — 각 행은 **해소 방향**(등재로 끝나는가 실환경 대체로 끝나는가) · **선행**(없으면 「없음」,
  그러면 그 행은 **착수 가능**) · **재검토 시점**(ISO 날짜 또는 관측 가능한 사건 — 다른 모델의 task id ·
  PR 번호 · 코드 리터럴. 날짜면 등재일로부터 최장 90일)을 **행 안에서 기계적으로 읽을 수 있게** 갖춰야
  한다. 산문에 섞여 있으면 사람은 읽어도 게이트와 감지는 못 읽으므로 미비로 센다. 셋 중 하나라도
  빠진 행의 수가 gap이다.
- **B4 소관 고정** — 원장에 올라온 차단 요인의 해소 주체는 **항상 이 모델**이다. 다른 모델·사람·외부로
  소관을 넘기는 것은 조건 없이 금지이며, 그래서 원장에 소관 칸을 두지 않는다. 기존 원장에 소관 칸이
  있으면 유효한 값은 「이 모델」 하나뿐이고, 다른 값이 적힌 행은 **이전 시도**로 보고 그 수를 gap으로 센다.
  이 모델이 받는 인계(B1)는 허용되지만 내보내는 인계는 없다.
- **B3 개수 변화** — 직전 관측 대비 **증가**면 새 부채이므로 새 행에 B1·B2를 적용하고, **감소**면
  그 행의 해소 방향이 실제로 반영됐는지 확인하며(예고만 하고 행이 사라지면 조용한 영구 면제다),
  **불변**이면 재검토 시점이 지난 행이 있는지만 본다. 절대 개수는 판정 기준에 넣지 않는다.

**판정 규칙**: B1 위반 ≥ 1 · B2 미비 ≥ 1 · B4 이전 시도 ≥ 1 · **착수 가능 행**(선행 「없음」) ≥ 1 ·
재검토 시점 도과 ≥ 1 · B3 감소인데 예고가 미반영 — 이 중 **하나라도** 참이면 `action_required`.
전부 거짓이면 `no_action_needed`로 닫아도 좋으나 그때도 **gap은 0이 아니다**: 잔여 행 수와 행별
재검토 시점을 `stateSummary`에 남기고 **가장 이른 재검토 시점**을 다음 감지의 관측 기준선에 적는다.
이것이 「성실히 등재할수록 문서는 충실해지는데 해소 압력은 그대로 0인」 성질을 막는 장치다.

**추적은 공짜다** — 원장이 to-be 슬라이스 안에 있으면 행이 늘거나 줄거나 내용이 바뀔 때 to-be
버전이 움직인다. 불변식 2는 새 `versionScript`를 요구하지 않고 **판정만** 요구한다. 원장을
{{POLICY_SSOT}} 밖에 두면 그 성질이 깨지므로 안에 둔다.

## 충돌 시 기본 방향
"실환경 우선"이 스펙이다.
- 미등재 모킹 → **먼저 실환경 대체가 가능한지 판정한다.** 가능하면 **이 task가 직접** {{ALTERNATIVES}}로
  대체를 구현하고 모킹을 제거한다. 대체 수단(fixture·시드·스텁 서버·클러스터 배포·테스트 진입점)이 아직
  없으면 **그것을 만드는 것까지 이 task의 범위**다 — E2E 스펙·하네스·매니페스트 수정을 포함하고, 제품
  코드도 테스트 진입점에 한해 포함한다. 실환경 대체가 불가능하다는 근거를 댈 수 있을 때만 카테고리
  등재+주석으로 간다.
- 대체를 한 슬라이스에 다 못 하면 나눠도 된다. 남은 부분은 원장에 행으로 남기고(B2), 그 해소도 이 모델이
  한다(B4). **다른 모델·사람에게 넘기는 것으로 닫지 않는다.**
- 고아 등재 → 허용목록에서 지운다.
- **차단 요인 → 계획이 비었으면 채우고, 착수 가능하면 이 task가 착수한다.** 적어 두는 것으로도, 소관을
  넘기는 것으로도 끝내지 않는다.
- 카테고리 판정이 애매하면 **제거 쪽으로 기운다**. 예외는 늘지 않는 방향으로만 관리한다.
